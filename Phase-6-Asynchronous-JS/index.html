Javascript Events

Q(1)What is the difference between synchronous and asynchronous javascript?

Answer:

Synchronous:Javascript is a single threaded which means one statement executes at a time. By default, JS is synchronous which means the next line should wait until the previous line finish execution.e.g.

  • console.log("Hi)
  • console.log("I am good")

Asynchronous:It lets slow work begin without blocking the rest of the program.Its result is handled later by using callbacks,promises,async and await.e.g.

  • console.log("Hi)
  • setTimeout(()=>{
     console.log("I am good")
    },2000)

Q(2)Why is js asynchronous even it is single threaded?

Answer:JS itself is single threaded. The asynchronous behaviour comes from the Javascript runtime which consists of:

  • Javascript Engine
  • Web APIs
  • Callback queue
  • Microtask queue
  • Event Loop

The browser provides Web API like:

  • setTimeout
  • fetch
  • DOM events
  • Geolocation
  • File API

Q(3)What is callstack?

Answer:A callstack is a data strucutre that stores function execution. When a function is called JS put it at the top of the task.When the task finish executing it removes the task.This keeps track of which function is currently running and where execution should return afterward.

e.g. function one() {
  two();
}
function two() {
  three();
}
function three() {
  console.log("Hello");
}
one();

Q(4)What is callback queue(task queue)?

Answer:A callback queue stores completed asynchronous callbacks until the callstack is empty.

e.g. console.log("Start");
setTimeout(() => {
  console.log("Timer done");
}, 0);
console.log("End");

Q(5)What is microtask queue?

Answer:A microtask queue is a high priority queue with small follow up async work- mainly promise handlers and async/await continuations.

e.g. console.log(1);
Promise.resolve().then(() => {
  console.log(2);
});
console.log(3);

Q(6)What is event loop?

Answer:An event loop is a mechanism which continuosly checks :

  • whether callstack is empty?
  • execute all Microtasks
  • execute one callback queue task
  • Repeat

Priority order:
Call Stack
  ↓
Microtask Queue
  ↓
Callback Queue

Q(7)What is callback function?

Answer:A callback function is a function which is passed as an argument to the other function and is executed later.

e.g.
function greet(name, callback) {
  console.log("Hello " + name);
  callback();
}
greet("John", function () {
  console.log("Finished");
});

Q(8)What is callback hell?

Answer:When the callback are nested deeply, the code becomes unreadable and hard to maintain.This situation is called callback hell.

login(function () {
  getUser(function () {
    getPosts(function () {
      getComments(function () {
      });
    });
  });
});

Q(9)What is promises?

Answer:Promise make handling asynchronous operations like API Calls, file handlings or time delays easier. It can be of 3 states: pending,fulfilled or rejected

const promise = new Promise((resolve, reject) => {
  let success = true;
  if (success)
   resolve("Success");
  else
   reject("Failed");
});

Q(10)Explain .then(),.cath() and .finally()

Answer:.then(),.catch() and .finally() are the methods which are used in promise.

.then:It runs when the promise succeeds.It receives the result .catch:It runs when thepromise fails.It receives the error .finally:It runs whether the promise succeeds or fails. use it for cleanup such as hiding a loading spinner. promise
  .then(result => console.log(result))
  .catch(error => console.log(error))
  .finally(() => console.log("Always runs"));

Q(11)What is promise chaining?

Answer:Promise chaninig allows you to execute a sequence of asynchronous operations in sequence. Each .then() returns a new promise, allowing further chaning. Error handling is easier with a single .catch() for the entire chain.

fetch(url)
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.log(err));

Q(12)What are promise methods?

Answer: promise.all():It returns a single promise that if resolves all then success is returned or fails if any one promise rejects.

const promise1=new Promise((resolve, reject) => {   setTimeout(()=>{
   resolve(1)
  },1000)
})
const promise2=new Promise((resolve, reject) => {
  setTimeout(()=>{
   reject("fails")
  },2000)
})
const promise3=new Promise((resolve, reject) => {
  setTimeout(()=>{
   resolve(3)
  },3000)
})
Promise.all([promise1,promise2,promise3])
  .then((results)=>{
   console.log(results)
})
  .catch((error)=>{
   console.log("error:",error)
  })

promise.allSettled():It waits for all promises to settled and returns the result whether succeed or fails.

Promise.allSettled([promise1,promise2,promise3])
 .then((results)=>{
   console.log(results)
 })
 .catch((error)=>{
   console.log("error:",error)
  })

promise.race():It returns a promise that fulfills or rejects.As soon as one of the promise in an iterable fulfills or rejects,it returns with the value or reason from that promise.

Promise.race([promise1,promise2,promise3])
  .then((results)=>{
    console.log(results)
  })
  .catch((error)=>{
    console.log(error)
  })

promise.any():It returns the first fulfilled promise and ignore the reject ones. Rejects only if all fails.

Promise.any([promise1,promise2,promise3])
  .then((results)=>{
    console.log(results)
  })
  .catch((error)=>{
    console.log(error)
  })

Q(12)What is async/await?

Answer:It allows to write asynchronous code in a clean,synchronus like manner, making it easier to read,understand and maintain while working with promises.

async function getUsers() {
  const response = await fetch(url);
  const data = await response.json();
  console.log(data);
}

by using try...catch

async function getData() {
 try {
   const res = await fetch(url);
   const data = await res.json();
   console.log(data);
 } catch (error) {
   console.log(error);
 }
}
